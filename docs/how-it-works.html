How it works

Herdr mods are JavaScript run by Herdr's native interface toolkit. There is no browser and no DOM. The mod is a view that Herdr redraws when its inputs change.

Files

FileRole
mod.jsonNames the mod and describes its overlay: a dialog 640 px wide.
main.jsThe view: reads agents and spaces from Herdr, builds the rows, draws them, handles keys and clicks, polls previews.
logic.jsPure helpers with no Herdr imports (durations, names, sorting, the status-time rule, selection). This is what the tests load under Node.
ask.jsPure: turns a terminal screen's text into the one line shown as the preview.
spinner.svg, search.svgThe two icons, drawn for this mod with currentColor.

Where the data comes from

  • Agents and spaces: Herdr's agents() and spaces() functions. agents() lists terminals whose program reports a status. Each agent has an address, status (blocked, done, working, idle), program, title, space and tab.
  • Theme: Herdr's theme(), so the dialog follows your layout's colors in light or dark.
  • Screens: hc read <address> --lines 60 through Herdr's hc function.
  • Shared values: attention.sort, agents.since, space.colors (see Configuration).

Preview polling

When the dialog opens, and then every 3000 milliseconds, the mod looks for blocked and done agents. If there are none it does nothing. Otherwise it reads their screens, at most 4 at a time, and only one pass runs at once: a tick that arrives while the previous pass is still running is skipped. A failed read stores an empty line so the placeholder does not stay forever. Previews for agents that are no longer waiting are dropped. The polling runs only inside the dialog's own view and is not started anywhere else; that it stops the moment the dialog closes has not been observed (see Verification status).

Status times

For each agent the mod picks the start of its current status from the first source that has one: shared agents.since, then the tab's working_since (working agents) or changed_at (others), then its own record. The record is a map from agent address to { s, at } (a status group and a time) kept in the mod's local storage under the key attention.seen. An entry is created the first time the dialog sees an address, replaced when the status changes (done and idle count as one status), and entries for addresses that no longer exist are removed (only while some agents exist, so an empty list during a reload does not wipe it). The record is written only when it changes, and at most 500 entries are read back. Every storage access is wrapped so a failure only means the first-seen times are not kept.

Selection and sorting

The selected row is remembered by the agent's address, not by its position, so a status change that reorders the list does not move your highlight to another agent. If the selected agent disappears the selection falls back to the first row. Changing the search or the sort resets it to the first row. The agents that need you and the finished ones are listed in the order Herdr last saw them change (Herdr's own sequence number), which can differ from the times shown beside them when those come from another source.

How a preview line is found

ask.js strips terminal color codes, removes box-drawing characters, drops empty lines and looks at the last 40. For a blocked agent it walks up from the bottom for a line that ends in a question mark, or in a yes/no hint after one, ignoring a leading selector arrow or number. Otherwise, and for finished agents, it takes the last message line (a line starting with a bullet such as •), skipping lines that look like tool calls such as Bash(...). The result is capped at 200 characters. The markers it recognizes are one constant at the top of the file.

Privacy and permissions

Herdr gives mods exec, fetch and file access and does not sandbox them. This mod uses none of them, apart from the one hc read call. That is this mod's own policy, checked by scripts/validate.mjs and by the rg commands in AGENTS.md; it is not a limit set by Herdr. You are trusting this code, not a sandbox, so read main.js if the table matters to you.

Does itAnswer
Read other terminals' screens?Yes, while the dialog is open, only for blocked and finished agents, through hc read. One line per agent is kept in memory and thrown away when the dialog closes. Nothing is written to disk or sent anywhere.
Store anything?Yes: a map from agent address to the time it was first seen in its status, in the mod's local storage, and your sort choice in Herdr's shared state. It holds no screen text.
Use the network?No.
Run programs?Only hc read. It never uses Herdr's general exec.
Read or write files?No. Herdr itself loads the mod's own icons.
Change your agents?No. Choosing a row focuses it (agent.focus). It sends no input to any terminal.

Editing it safely

Herdr reloads a mod the moment a file in its folder is saved. Editing the folder in your live Herdr home changes your screen immediately, including half-finished edits. Work in a copy elsewhere, run herdr-app check on that copy, and copy it in last. The repository's AGENTS.md and CONTRIBUTING.md cover this for agents and contributors.
