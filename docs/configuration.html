Configuration

There is no settings file. What can be configured is the key, one prop, and a few constants at the top of main.js. Layout authors can also feed it two shared values.

Key binding

The repository's keys.json binds Ctrl+Shift+A in global and terminal to the command mod.open:attention-picker. Change the left side to any key Herdr accepts. Herdr applies keys.json live. See Install.

Props

Props are given by whatever opens the overlay. Opening it with its key passes none, so the search box is on.

PropValuesEffect
searchfalse or anything else, including absentAbsent or any value except false shows the search box. false gives the keys-only variant with 1-9 jump badges.
overlaysupplied by Herdr, read onlyThe overlay's id. The mod passes it to closeOverlay to close itself, and runs the overlay.close command instead when it is missing. Do not set it.

To open it from your own mod:

openOverlay({ mod: "attention-picker", kind: "dialog", width: 640, props: { search: false } });

The overlay description in mod.json is a dialog 640 px wide.

Shared keys

Herdr keeps a small key-value store that every mod can read. This mod uses three keys and keeps its names stable so other layouts can rely on them.

KeyMod accessMeaning
attention.sortreads and writesrecent, oldest or space. Any other value is read as recent.
agents.sincereads onlyAn object from agent address to the epoch milliseconds when it entered its status. Optional. When present it wins over the mod's own tracking. The mod never writes it.
space.colorsreads onlyAn object from space id to a color: an ansi1 to ansi6 name from the theme, or a #rgb, #rrggbb or #rrggbbaa value (the alpha is dropped). Optional; spaces without an entry, and entries the mod cannot read (a number, null, a list, an unknown name), use teal (ansi6).

For layout authors

You do not need to publish anything: the mod works alone. Publish agents.since only if your layout already tracks status times, so both show the same number. Publish space.colors if your layout colors spaces and you want the dialog to match.

  • agents.since is an object { "<agent address>": <epoch ms> }: the moment that agent entered its current status. Values must be positive numbers; anything else is ignored for that agent.
  • space.colors is an object { "<space id>": "ansi1".."ansi6" | "#rrggbb" }.
  • Herdr saves shared state to shared.json, so these values survive a restart, and so does a stale one. Write agents.since every time an agent changes status, and delete the entries of agents that are gone.
  • Staleness: the mod ignores a shared time for a blocked or working agent that is alone in its tab when the tab shows a change more than 10 seconds newer. That is a partial guard; for any other agent a shared time always wins. A value the mod can trust completely needs your layout to keep it current.
import { agents, shared, setShared } from "herdr";
const last = new Map(); // address -> the status you saw last time
function publish() {
  const old = shared("agents.since") ?? {}, since = {};
  for (const a of agents()) {
    since[a.address] = last.get(a.address) === a.status && old[a.address] ? old[a.address] : Date.now();
    last.set(a.address, a.status);
  }
  setShared("agents.since", since); // a fresh object drops agents that are gone
}

Call publish() from a timer or from whatever your layout already runs when agents change. The example is a sketch: it has not been run.

The command it runs

Choosing an agent runs Herdr's agent.focus command with that agent's terminal address, then closes the dialog.

Constants

These are named at the top of mods/attention-picker/main.js. Edit a copy, not the live folder (see How it works). The page is checked against the code by scripts/check-docs.mjs where the script knows the constant. Two more live in logic.js: STALE_SLACK (10000 ms, the margin of the stale-time guard) and RECHECK (10, the most passes a settled screen is skipped).

LIST_H320 (pixels)The tallest the list grows before it scrolls. The dialog needs a window at least about 440 px tall to show it whole.
