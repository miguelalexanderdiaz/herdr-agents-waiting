Troubleshooting

Some behavior has not been watched in a live window yet. Where an entry depends on it, it says so and points to Verification status.

The key does nothing

  • Check that the line is in both the global and the terminal section of keys.json, and that the file is valid JSON (a trailing comma is the usual culprit).
  • Another key or a program in your terminal may use Ctrl+Shift+A. Bind a different key (Configuration).
  • Open it without the key to separate the problems: herdr-app do mod.open '{"name":"attention-picker"}'. If that works, the binding is the issue. If not, the folder is. (Quoting differs on Windows.)
  • herdr-app check ~/.config/herdr-app/mods/attention-picker reports problems in the mod itself. It does not catch a renamed folder with an unchanged HOME, a broken mod.json or a missing key; node scripts/verify-install.mjs <mod folder> --home <Herdr home>, run from a clone of this repository, does (see Install).

Another binding wins, or the key reaches my terminal program

  • A focused terminal uses the terminal section of keys.json, which is more specific than global. Without a terminal entry the key goes to the program in the terminal. Add the same line to both sections.
  • A layout:<name> section in keys.json (named after the active layout) can override both. If Ctrl+Shift+A is already bound there, change or remove that line, or bind another key.

The key does not close the dialog

Esc always closes it. Pressing the key again should, because Herdr's mod.open toggles, but whether the key reaches Herdr while the search box has focus has not been observed. If it does not, use Esc and tell us your Herdr version and OS.

No spinner or search icon

The icons are loaded from mods/attention-picker/. If you renamed the folder, change the HOME constant in main.js to match. If the two .svg files are missing, copy the whole folder again.

There is no search box

Something opened it with search: false and you are in the keys-only variant (1-9 jump badges). Open it with its own key to get the search box.

It says "No agents running"

The dialog lists agents only: terminals whose program reports a status to Herdr, the same list Herdr's agent panels use. A plain shell does not count, so a window full of shells shows the empty state. Start an agent in a terminal and it appears. If you do have agents running and still see it, report it with your Herdr version.

A finished agent disappeared from the top

That is expected. Herdr calls an agent finished (done) only until you have looked at it, here or on another Herdr client, and then calls it idle. An idle agent sits under the rule with the others.

Times are missing or look wrong

  • A time only shows once the mod has a start for that agent. See Waiting times: it comes from agents.since, the tab, or the first time the dialog saw the agent.
  • If the mod's local storage is unavailable, first-seen times cannot be kept and are re-learned on each open.
  • The mod can only date a change it was open to see. An agent that finished while the dialog was closed counts from the tab's changed_at if there is one, or from the next time you open it.
  • A shared agents.since left by a layout you stopped using can be stale and still wins in some cases. Remove that value from Herdr's shared state if you no longer run that layout.

The second line is blank, or shows an ellipsis

  • An ellipsis is shown until the first read returns, normally under a few seconds.
  • A blank line means no question or message was recognized on that terminal's screen. Recognition is tuned to Claude Code style screens (see Previews). Other agents may show nothing; selecting the row still works.
  • A blocked agent whose question is further back than the last 40 non-empty lines of its text may show an older line, or nothing.

The dialog is clipped in a small window

The dialog is 640 px wide (mod.json) and its list is up to 320 px high (LIST_H in main.js), so showing everything takes a window about 440 px tall. In a smaller window the list may shrink and scroll, or the dialog may be cut off; this has not been tried. Make the window taller, or zoom out with Herdr's app.zoom_out command.

The mod did not install, or replaced mine

Do not overwrite a mod with the same name. Install under another name and change the folder, the HOME constant and the keys.json line (Install).

Running the command from a terminal

On macOS and Linux shells the JSON goes in single quotes:

herdr-app do mod.open '{"name":"attention-picker"}'

Herdr's help also shows arguments given as flags, which needs no JSON quoting: herdr-app do mod.open --name attention-picker. Neither form has been tried here.

On Windows the quoting of the JSON form depends on the shell (PowerShell and cmd.exe treat quotes differently, and PowerShell may need the inner quotes escaped). This has not been tried on Windows. The simple routes are the key, the command palette, or the flag form above.

Windows or Linux

The mod has no operating-system code, but nobody has run it in Herdr on Linux or Windows. CI (.github/workflows/ci.yml) runs the checks and unit tests on Linux, Windows and macOS, each on Node 22 and 24; that covers the code, not the mod inside Herdr. If something differs, open an issue with your OS, Herdr version (herdr-app --version) and what you saw. Herdr's home folder may be elsewhere than ~/.config/herdr-app; use the folder your install says.

The original mod ran in the author's Herdr on macOS (0.1.12). Reporting a problem

Open an issue on the repository; the form (bug_report.yml) asks for your Herdr version (herdr-app --version), OS, what you pressed and what you saw. Do not paste terminal contents you would not want public. For a security problem, such as the mod reaching something it says it does not, follow SECURITY.md and report it privately.
